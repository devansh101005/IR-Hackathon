CSD358 IR Hackathon · Track T5 · Multilingual and Indic search

One question. Every script.

Most people type Hindi in Roman letters, and everyone spells it a little differently. Most Hindi text on the web is written in Devanagari. A normal search engine matches exact words, so kal ka mausam finds nothing about कल का मौसम. LipiSetu (लिपि = script, सेतु = bridge) fixes this with classic IR.

How to use this page

  1. Type a question in any script, or click an example below the search box.
  2. Pick a system. LipiSetu (S3) is the main one; Transliterate + BM25 (B2) is the obvious baseline.
  3. Read the right-hand panel. It shows every step the engine took: tokens, sound keys, df and idf, real postings, and the gate decision.
  4. Scroll down for how it works, the measured results, the human query set and a glossary.

    Step 3 · Evidence

    Measured, not claimed

    Every number below is read live from the results/ folder: 350 MIRACL-Hindi test queries (dev split), each asked in three forms: Devanagari, standard Roman and casual Roman. All tuning used the separate train split only.

    How to read: one group of three bars per system. Blue = question in Devanagari, orange = standard Roman, green = casual Roman. Higher is better (1.0 = perfect ranking). A script-invariant system has three bars of the same height.

    2 · Quality vs neural compute (the gate)

    How to read: left to right, more queries run the expensive neural stage. Blue = our learned gate picks which queries; orange = a random gate with the same budget. The dot is the threshold chosen on the train split.

    3 · Which Dhvani rules matter (ablation)

    How to read: each row switches one rule of the sound key off and rebuilds the Dhvani zone. If Roman nDCG drops a lot, that rule matters. "Words per key" shows how many different words share one key (more = more merging).

    4 · Speed per system

    How to read: median and 95th-percentile time per query on a laptop CPU (no GPU). Sparse systems answer in milliseconds; neural ones cost more, which is why the gate exists.

    Step 4 · Real people, real spellings

    The human query set

    Three of us typed the same 60 test questions in Roman letters, on our own, without any transliteration tool. Each of us also wrote code-mixed and English versions of 20 of them. This checks whether the system works on how people really type, not only on our generated variants.

    5 · Same word, three people

    How to read: each row is one word from a question, as each annotator typed it, with its Dhvani key. ✓ = all three keys are the same, so the engine treats the spellings as one word.

    6 · Search quality on the human queries (nDCG@10)

    How to read: "Roman A1–A3" are the three annotators' own romanisations. Green marks the best system in each column.

    Words used on this page

    Glossary

    Dhvani key

    A sound code for a word. Consonant sounds are kept, vowels and aspiration are dropped, so mausam, mosam and मौसम all become MSM.

    Zone

    A separate part of the index. LipiSetu has a surface zone (exact words), a title zone and a Dhvani zone (sound keys). Each zone is scored and the scores are added with weights.

    df and idf

    df = how many passages contain a term. idf = log of (N / df), so rare terms count more than common ones.

    Pooled df

    One word can have many spellings, and each spelling alone looks rare. Pooled df gives every spelling the df of its whole sound class, so the idf is not inflated.

    BM25

    The ranking formula: rewards a term appearing in a passage, with diminishing returns for repeats, and normalises for passage length.

    Proximity

    Passages where the query words appear close together rank higher. We use the smallest window that contains all query words.

    Postings

    For each term, the list of passages that contain it, with how often (tf) and at which word positions.

    nDCG@10

    The main quality score: 1.0 means the relevant passages are at the very top of the first 10 results, 0 means none were found.

    Script Gap

    nDCG@10 for Devanagari questions minus nDCG@10 for the same questions in Roman. 0 = the script does not matter.

    RBO / CSC@10

    How similar two ranked lists are, giving more weight to the top. 1.0 = identical top 10 for both scripts.

    Gate

    A small logistic-regression model that reads signals from the fast search and decides whether the slow neural stage is worth running.

    Distillation (SCD)

    We trained a small query encoder so that a Roman question lands at the same point as its Devanagari version. Then we shrank it from 448 MB to 37 MB.
